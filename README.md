# 마켓컬리 이미지 데이터 수집

문맥 활용에 따른 대체텍스트 품질 변화 분석에 사용할 데이터를 수집한다.
수집한 데이터는 **`data` 브랜치에 카테고리별로 업로드**한다.

## 1. 수집 범위

이번에는 카테고리별로 추천순 상위 50개 상품을 선정하고, 상품당 대표 이미지와 상세 이미지를 각각 1장씩 수집한다.

| 구분 | 기준 |
| --- | --- |
| 수집 대상 | 마켓컬리 상품 페이지 |
| 카테고리 | 간편식·밀키트·샐러드 / 과일·견과·쌀 / 베이커리 / 채소 |
| 상품 선정 | 수집 시점의 카테고리별 추천순 상위 50개 |
| 상품당 이미지 | 대표 이미지 1장 + 상세 이미지 1장 |
| 카테고리별 목표 | 상품 50개, 이미지 100장 |
| 전체 목표 | 상품 200개, 이미지 400장 — 카테고리별 합계 기준 |
| 저장할 데이터 | 이미지 파일 + 이미지별 메타데이터 CSV |

CSV는 **이미지 1장당 1행**으로 작성한다. 상품 1개당 2행이므로, 카테고리별로 헤더를 제외한 100행을 저장한다.

위 수량은 수집 목표다. 카테고리 간 중복 상품이 있으면 `product_id`를 기준으로 전체 고유 상품 수를 따로 확인한다.

## 2. 카테고리 및 담당

| 카테고리 | 담당 | 영문 폴더명 | 수집 페이지 |
| --- | --- | --- | --- |
| 간편식·밀키트·샐러드 | 김은영 | `convenience_meals` | [카테고리 912](https://www.kurly.com/categories/912) |
| 과일·견과·쌀 | 윤서현 | `fruits_nuts_rice` | [카테고리 908](https://www.kurly.com/categories/908) |
| 베이커리 | 조해인 | `bakery` | [카테고리 915](https://www.kurly.com/categories/915) |
| 채소 | 김은영 | `vegetables` | [카테고리 907](https://www.kurly.com/categories/907) |

영문 폴더명은 위 표를 기준으로 통일하는 안이다. CSV의 `category` 값에도 같은 영문명을 사용한다.

## 3. 폴더 구조 및 파일명

`data`는 **폴더명이 아니라 브랜치명**이다. 해당 브랜치의 저장소 최상위에 카테고리별 폴더를 만든다.

```text
Capstone-Design-Alt-Text/
├── README.md
├── convenience_meals/
│   ├── convenience_meals_metadata.csv
│   └── images/
├── fruits_nuts_rice/
│   ├── fruits_nuts_rice_metadata.csv
│   └── images/
├── bakery/
│   ├── bakery_metadata.csv
│   └── images/
└── vegetables/
    ├── vegetables_metadata.csv
    └── images/
        ├── kurly_5085771_1.jpg
        └── kurly_5085771_2.jpg
```

상품 ID `5085771`은 파일명 형식을 설명하기 위한 예시다.

## 4. 수집 항목

CSV는 아래 **10개 컬럼의 이름과 순서**에 맞춰 작성한다.

| 변수명 | 내용 | 저장 기준 |
| --- | --- | --- |
| `product_id` | 상품 식별번호 | 문자열로 취급 |
| `product_name` | 상품명 | 페이지에 표시된 상품명 |
| `category` | 수집 카테고리 | 2절의 영문 폴더명과 동일 |
| `product_url` | 상품 페이지 URL | 전체 URL |
| `image_id` | 수집 후 부여하는 이미지 식별번호 | 카테고리별로 1부터 순서대로 부여하는 안 |
| `image_position` | 대표 / 상세 이미지 구분 | 대표 `1`, 상세 `2` |
| `image_url` | 원본 이미지 URL | `src` 등에서 확인한 실제 수집 대상 이미지 URL |
| `original_alt` | 기존 대체텍스트 | 해당 이미지의 `alt` 속성값 원문 |
| `alt_exists` | `alt` 속성 존재 여부 | 속성 있음 `1`, 없음 `0`으로 구분하는 안 |
| `crawl_date` | 수집일 | `YYYY-MM-DD`, 한국시간 기준 |

### 기존 alt 저장 기준 — 제안

`alt_exists`는 설명 문장의 유무가 아니라 **`alt` 속성 자체의 유무**로 구분하는 안이다. 빈 `alt`와 속성 누락을 따로 기록한다.[3]

| 원본 상태 | `original_alt` | `alt_exists` |
| --- | --- | --- |
| `alt="상품 설명"` | `상품 설명` | `1` |
| `alt=""` | 빈 문자열 | `1` |
| `alt` 속성 없음 | 빈 문자열 | `0` |

기존 alt는 수정하지 않고 그대로 보관한다. 값이 없거나 부적절해 보여도 상품명이나 생성 캡션으로 채우지 않는다.

`alt_exists`는 속성 유무를 기록하는 값으로만 사용하며, 대체텍스트 품질을 나타내는 값으로 사용하지 않는다.

## 5. 수집 기준 및 예외 처리

### 상품 선정

카테고리에서 추천순으로 정렬한 뒤, 서로 다른 `product_id` 기준 상위 50개 상품을 수집한다. 처음 선정한 상품 목록은 보관하고, 누락분을 재수집할 때도 같은 목록을 사용한다.

### 이미지 선정

대표 이미지는 상품 페이지의 기본 대표 이미지 1장을 수집한다.

상세 이미지는 상품 설명 영역에서 위에서 아래로 확인해, 대표 이미지와 중복되지 않는 첫 번째 상품 관련 이미지를 선택하는 안이다. 공통 배송 안내, 광고 배너, 아이콘 등은 제외한다.

**상세 이미지 선택 기준은 팀에서 확인한 뒤 통일한다.**

### 수집이 어려운 경우

상세 이미지가 없거나 다운로드에 실패하면 해당 상품 ID와 사유를 기록한다. 대표 이미지를 복제해서 이미지 수를 맞추지 않는다.

다음 순위 상품으로 대체할지는 팀에서 결정한다.

## 6. 업로드 전 확인

- [ ] 카테고리 폴더명과 CSV 파일명이 규칙에 맞는지 확인한다.
- [ ] CSV의 10개 컬럼명과 순서가 일치하는지 확인한다.
- [ ] 상품 50개, 이미지 100장, CSV 100행인지 확인하고 부족분을 기록한다.
- [ ] 상품별 대표 / 상세 이미지가 각각 1장이고, 실제 파일이 정상적으로 열리는지 확인한다.
- [ ] CSV의 상품 ID·이미지 구분이 파일명과 맞는지, 기존 alt가 원문 그대로 저장됐는지 확인한다.

확인이 끝난 데이터는 `main`이 아닌 **`data` 브랜치의 담당 카테고리 폴더**에 업로드한다.
